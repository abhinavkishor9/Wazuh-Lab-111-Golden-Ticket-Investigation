# Troubleshooting Notes

## 1. Issue: No Results for Authentication Event Queries

### Observation

The initial PowerShell query returned zero matching records for Event IDs 4624, 4672, 4768, and 4769 within the previous seven days.

### Investigation

The Security log was queried separately without suppressing errors. Windows returned recent records, including Event IDs 4719, 6417, and 4688.

The Security channel was confirmed to be enabled, with 1,692 records reported at the time of the check.

### Resolution

The initial zero-result output was not caused by an inability to read the Security log. The next check was to inspect the audit policy and relevant event availability.

## 2. Issue: Logon Auditing Disabled

### Observation

The audit policy reported:

- Logon: No Auditing
- Special Logon: No Auditing

### Impact

The disabled success-auditing settings explained why expected successful-logon and special-privilege events might not have been generated during the initial investigation period.

### Corrective Action

Success auditing was enabled for both subcategories during the lab.

```powershell
auditpol /set /subcategory:"Logon" /success:enable
auditpol /set /subcategory:"Special Logon" /success:enable
```

The policy can be checked using:

```powershell
auditpol /get /subcategory:"Logon"
auditpol /get /subcategory:"Special Logon"
```

These changes affect subsequent auditing. They do not retroactively create missing events.

## 3. Issue: Events 4768 and 4769 Not Available Locally

### Observation

The workstation query did not return Event IDs 4768 or 4769.

### Root Cause Assessment

The endpoint reported:

- Domain: `WORKGROUP`
- PartOfDomain: `False`
- DomainRole: `0`

The workstation was not joined to an Active Directory domain and was not a domain controller.

### Resolution

No Discover query or workstation audit-policy change can substitute for missing domain-controller telemetry.

A full Golden Ticket investigation requires access to appropriate Active Directory domain-controller Security logs and correlated evidence.

## 4. Wazuh Security Channel Configuration

### Observation

The agent configuration contained:

```xml
<localfile>
  <location>Security</location>
  <log_format>eventchannel</log_format>
  ...
</localfile>
```

The configuration also contained a collection block for:

`Microsoft-Windows-Sysmon/Operational`

### Assessment

The configuration demonstrated that both channels were included in the agent setup. It did not, by itself, prove that all matching records reached the manager or appeared in the alert index.

The Security-channel query excluded event IDs 5145, 5156, and 5447 among others. These exclusions did not directly account for the missing target event IDs.

## 5. Issue: Event Visibility in Discover

### Observation

A Security Event ID 4672 record was visible in Wazuh Discover.

### Assessment

This confirmed that at least one relevant Security event was available in the alert index.

The presence of one event does not establish that all Security events were collected. Wazuh alert indexes contain alerts generated by rules and should not automatically be treated as complete archives of every event received.

### Recommended Checks

1. Confirm the event exists in the local Windows Security log.
2. Confirm the event timestamp and event record ID.
3. Inspect the agent's collection configuration.
4. Check agent connectivity and manager-side event processing.
5. Inspect the actual indexed document fields before adjusting Discover queries.
6. Check raw event archives only if archive collection and indexing are configured.
